# AltRouter — руководство пользователя

Панель роутера доступна по `https://<адрес-роутера>:9000` (самоподписанный сертификат — браузер попросит подтвердить исключение). Вход по имени пользователя и паролю; сессия хранится в cookie и завершается при рестарте службы панели.

## Разделы панели

| Раздел | Что настраивается |
|---|---|
| **Системный монитор** | Загрузка CPU/памяти, трафик интерфейсов, список клиентов (обновляется в реальном времени) |
| **Интернет** | WAN- и LAN-порты: роль (wan/lan/off), DHCP/статика/PPPoE, MAC, MTU, VLAN, DNS; политики WAN — режим failover/balance, приоритеты, веса, Ping Check |
| **Домашняя сеть** | Сегменты (мосты из LAN-портов), адрес подсети, DHCP (пул, аренда, DNS), резервирования IP↔MAC |
| **Сетевые правила** | Файрвол (forward/input, зоны wan/lan/сегменты), переадресация портов (DNAT), локальные DNS-имена, статические маршруты |
| **VPN** | WireGuard — экспериментальный раздел, не поддерживается |
| **Управление** | Пользователи панели, резервная копия/восстановление, журнал транзакций, диагностика (ping, traceroute, tcpdump), системный журнал, SSH, TLS, доступ, обновления, питание, смена пароля |

## Транзакции и подтверждение изменений

Каждое сетевое изменение (интерфейсы, сегменты, WAN, правила) работает как транзакция:

1. После сохранения новые конфиги применяются, а сверху страницы появляется баннер: **«Подтвердить / Откатить»** и таймер.
2. Если интернет и доступ к панели работают — нажмите **Подтвердить** до истечения таймера.
3. Если доступ пропал — через **~3 минуты** изменения откатятся автоматически, вернётся прежняя рабочая конфигурация.
4. Откатить вручную можно кнопкой **Откатить** в баннере.
5. История (применена/подтверждена/откачена) — в **Управление → Журнал**.

Правила безопасности: не отключайте порт/сегмент, через который вы подключены к панели; при двух WAN не выключайте оба сразу — доступ будет потерян до автоотката.

## Типовые сценарии

**Два провайдера (failover).** Интернет → оба порта в роли WAN (DHCP). В политиках WAN режим `failover`: приоритет 1 — главный канал, 2 — резервный. Ping Check (цель, интервал, порог неудач) переключает канал при пропадании связи.

**Два провайдера (балансировка).** Режим `balance`: приоритет задаёт порядок (метрика = приоритет×100), вес (1–100) — долю трафика. Пример: вес 3 и 1 ≈ 75%/25%. Ping Check выведет упавший канал из ротации.

**Гостевой сегмент.** Домашняя сеть → новый сегмент: id (`a-z0-9-`, до 9 символов), порты, адрес с префиксом (`192.168.10.1/24`), DHCP-пул без адреса сети, broadcast и адреса роутера. Порты сегмента объединяются в мост.

**Постоянный адрес устройству.** Домашняя сеть → сегмент → резервирования: MAC + IP из подсети сегмента (+ имя хоста, комментарий).

**Доступ к сервису из интернета.** Сетевые правила → Переадресация портов: WAN (или все), протокол tcp/udp, внешний порт или диапазон (`8000-9000`), IP назначения и порт (диапазоны должны совпадать по размеру).

**Закрыть/разрешить трафик.** Сетевые правила → Файрвол: направление `forward` (между зонами) или `input` (к самому роутеру), зона-источник (`wan`, `lan`, id сегмента), протокол, адрес/порт источника и приёмника, действие `allow`/`drop`. Порты указываются только для tcp/udp.

**Имя для устройства в локальной сети.** Сетевые правила → Локальные DNS: hostname + IP — запись раздаётся клиентам через dnsmasq.

**Маршрут в другую сеть.** Сетевые правила → Статические маршруты: подсеть назначения (`10.5.0.0/16`), шлюз, при необходимости интерфейс и метрика (1–10000).

**Диагностика.** Управление → ping/traceroute (с указанием интерфейса), tcpdump (ограниченное время захвата), системный журнал.

**Резервная копия.** Управление → скачать архив (учётные записи + network.json + журнал); восстановление загружает такой же архив. Сетевые бэкапы также лежат на роутере в `/etc/altrouter/network/backups/`.

## API

Интерактивная спецификация: `https://<адрес-роутера>:9000/api/docs` (OpenAPI). Все мутирующие сетевые методы работают через ту же транзакцию, что и UI.
