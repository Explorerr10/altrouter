# AltRouter — формат конфигурации

Состояние хранится в `ALTROUTER_CONFIG_DIR` (по умолчанию `/etc/altrouter`) в виде JSON. Все поля валидируются pydantic-моделями; ошибки валидации возвращаются API с понятным текстом на русском. Ниже — полная схема `network.json`; сопутствующие файлы описаны в руководстве по развёртыванию.

## `config.json` — учётные записи панели

Создаётся автоматически (`UsersStore`): имя пользователя, хеш пароля, флаг `default_password`. Правится через `/api/system/users` и смену пароля.

## `network/network.json` — желаемое состояние сети

```json
{
  "items":     { "<iface>": { InterfaceConfig } },
  "segments":  [ SegmentConfig ],
  "routes":    [ StaticRoute ],
  "wan":       { "mode": "failover|balance", "policies": { "<iface>": WanPolicy } },
  "rules":     [ FirewallRule ],
  "forwards":  [ PortForward ],
  "dns":       [ DnsRecord ],
  "wireguard": [ WireguardInterface ]
}
```

### items: InterfaceConfig (на каждый физический порт)

| Поле | Тип | Правила |
|---|---|---|
| `name` | str | `^[a-zA-Z0-9._-]{1,15}$`, `lo` запрещён |
| `role` | str | `wan` \| `lan` \| `off` |
| `ipv4` | str | `dhcp` \| `static` \| `pppoe` |
| `address` | str? | только для static, IPv4 с префиксом (`192.168.1.1/24`); LAN — только static |
| `gateway` | str? | только static-WAN, IPv4 в подсети адреса; LAN запрещён |
| `dns` | [str] | только WAN, IPv4-адреса (строка `1.1.1.1,8.8.8.8` принимается) |
| `mtu` | int? | 68–65535 |
| `vlan_id` | int? | 1–4094 |
| `mac` | str? | только WAN, `aa:bb:cc:dd:ee:ff` |
| `pppoe_username/password` | str? | только WAN+pppoe; логин обязателен; без кавычек, `\`, переводов строк; address/gateway при pppoe запрещены |

`off` — все прочие поля должны быть пустыми.

### segments: SegmentConfig

| Поле | Тип | Правила |
|---|---|---|
| `id` | str | `^[a-z0-9][a-z0-9-]{0,8}$` (до 9 символов) |
| `name` | str | 1–64 символа |
| `interfaces` | [str] | ≥1 LAN-порт, без повторов; порты мостятся |
| `address` | str | IPv4 с префиксом, адрес роутера в этой подсети |
| `dhcp` | DhcpSettings | `enabled`, `pool_start`, `pool_end` (IPv4 внутри подсети, начало < конца, без адреса сети/broadcast/роутера), `lease_hours` 1–8760 (по умолч. 12), `dns` [IPv4] |
| `reservations` | [Reservation] | `mac` + `ip` (уникальные, IP в подсети сегмента), `hostname`?, `comment`? ≤64 |

### routes: StaticRoute

`dest` — IPv4-подсеть (`10.5.0.0/16`), `gateway` — IPv4, `iface`?, `metric`? 1–10000.

### wan: WanConfig

- `mode`: `failover` (по умолчанию) или `balance`.
- `policies` по имени WAN-интерфейса:
  - `priority` 1–99 (нет = вне игры); метрика main-default = `priority*100`;
  - `weight` 1–100 — доля трафика в режиме balance;
  - `ping_check`: `enabled` (по умолч. false), `target` (IP/hostname, по умолч. `1.1.1.1`), `interval_s` 5–3600 (30), `fail_threshold` 1–20 (3).

### rules: FirewallRule

| Поле | Значения |
|---|---|
| `direction` | `forward` (между зонами, по умолч.) \| `input` (к роутеру) |
| `zone` | `wan` \| `lan` \| id сегмента |
| `proto` | `any` (по умолч.) \| `tcp` \| `udp` |
| `action` | `allow` (по умолч.) \| `drop` |
| `src_ip`, `dst_ip` | IPv4-адрес или подсеть |
| `src_port`, `dst_port` | порт или диапазон `8000-9000` (1–65535, начало < конца); только для tcp/udp |
| `comment` | ≤64 символов |

### forwards: PortForward (DNAT)

`wan`? (имя интерфейса; нет = все WAN), `proto` `tcp`|`udp` (по умолч. tcp), `port` — внешний порт/диапазон, `to_ip` — IPv4, `to_port`? — того же размера, что внешний диапазон, `comment`? ≤64.

### dns: DnsRecord (локальные имена через dnsmasq)

`hostname` (FQDN-подобное имя), `ip` (IPv4), `comment`? ≤64.

### wireguard: WireguardInterface

Экспериментальный раздел (этап 5 пропущен): интерфейс + пиры, ключи генерирует `GET /api/network/keypair`. Конфигурация хранится, но раздел считается неподдерживаемым.

## Транзакционные файлы

PUT-запросы не меняют `network.json` напрямую:

1. `PUT ...` → валидация → запись `network.json` + генерация `staging/` (networkd `.network`, dnsmasq, nftables) + снимок старого staging в `backups/<ts>-<tx>/` + `pending.json` + запись в `journal.jsonl`; конфиги применяются хелпером `altrouter-netapply`.
2. `POST /api/network/interfaces/confirm` — транзакция подтверждается, `pending.json` удаляется.
3. `POST /api/network/interfaces/rollback` (или таймаут `ALTROUTER_CONFIRM_TIMEOUT`) — staging восстанавливается из бэкапа, `network.json` откатывается.

Пример рабочего `network.json` (сервер приёмки): WAN `enp5s0`/`enp6s0` (DHCP, mac), LAN `enp7s0`+`enp8s0` в сегменте `test` (192.168.1.1/24, DHCP .10–.99/12h), WAN mode balance с политиками 3:1.
